# CheersAI脱敏沙箱用户说明书

## 1. 文档目的与适用对象

本说明书用于帮助企业用户、个人用户、部署管理员与技术支持人员快速理解并使用 CheersAI脱敏沙箱。

适用对象如下：

- 需要在对外发送文件前完成敏感信息处理的办公用户
- 需要在与 AI 智能体或大模型交互前先做内容清洗的个人与团队
- 需要在企业内部落地数据脱敏流程的管理者
- 负责安装、部署、运维和支持的技术人员

本文采用以下阅读约定：

- 页面名称、按钮名称、接口路径使用代码样式标记
- “可选”表示该能力不是默认必需项
- “管理员”指负责企业内网部署、OCR 组件、FileBay 配置和运行环境维护的人员

## 2. 软件概览

### 2.1 产品定位

CheersAI脱敏沙箱是一款面向企业与个人用户的本地敏感文件脱敏开源软件。它用于在文件外发、资料共享、审阅流转，以及与 AI 智能体或大模型交互前，先对姓名、电话、证件号、邮箱、地址、客户信息、项目代号等敏感内容进行处理；在任务完成后，再根据本地保留的映射规则一键恢复需要还原的信息。

### 2.2 版本与部署形态

| 形态 | 主要使用者 | 典型场景 | 说明 |
|---|---|---|---|
| 桌面版 | 个人用户、单机办公用户 | 本机处理、离线处理、本地规则管理 | 基于 Tauri 运行 |
| 浏览器版 | 企业内网用户 | 团队共享使用、统一部署、集中运维 | 由 Nginx + Runtime 提供服务 |
| 本地 Docker 验证环境 | 开发与测试人员 | 快速联调、验证浏览器端链路 | 适合本地验证，不等同正式生产交付 |

### 2.3 典型使用流程

```text
选择文件
  ↓
选择脱敏规则或敏感词库
  ↓
生成脱敏预览
  ↓
确认生成正式结果
  ↓
对外发送或交给 AI 使用
  ↓
需要恢复时执行反脱敏
```

## 5. 安装与部署指南

### 5.1 桌面版源码运行

适合研发、测试或需要本地调试的用户。

1. 安装依赖环境：
   - `Node.js 22+`
   - `pnpm 11+`
   - `Rust 1.85+`
2. 在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm tauri dev
```

3. 如需构建安装包，可按目标平台执行：

```bash
pnpm tauri build
pnpm build:windows
pnpm build:linux
```

本地联调补充说明：

- 若本地调试需要沿用 CheersAI Desktop 在线工作区中的 FileBay 配置，可先在对应在线工作区完成登录与配置同步，再返回本软件刷新 FileBay 状态
- 这条路径主要用于开发调试便利，不属于正式企业部署的标准流程

### 5.2 本地 Docker 验证

适合快速验证浏览器端与 Runtime 联调。

1. 在仓库根目录执行：

```bash
docker compose up -d --build
```

2. 打开以下地址确认服务可用：
   - 浏览器端： `http://127.0.0.1:5173`
   - 健康检查： `http://127.0.0.1:5173/api/v1/health`

3. 如需停止环境：

```bash
docker compose down
```

### 5.3 企业内网部署

适合企业统一提供浏览器入口。

高层步骤如下：

1. 构建 Runtime：

```bash
cargo build --release --manifest-path apps/vault-runtime-api/Cargo.toml
```

2. 构建浏览器端静态资源：

```bash
pnpm install --frozen-lockfile
pnpm exec vite build
```

3. 配置 Runtime 环境变量、OCR 组件与 FileBay 参数
4. 使用 systemd 托管 Runtime 进程
5. 使用 Nginx 托管前端并反向代理 `/api`
6. 执行部署后联通性检查与黑盒测试

企业部署的详细步骤请参考：

- [`docs/enterprise/DEPLOYMENT.md`](./enterprise/DEPLOYMENT.md)
- [`deploy/linux/README.md`](../deploy/linux/README.md)

### 5.4 卸载与清理建议

执行卸载或环境清理前，请先完成以下操作：

- 备份仍需保留的脱敏结果与映射文件
- 导出仍需保留的敏感词库
- 如已配置 FileBay，确认是否需要撤销或轮换访问令牌
- 企业部署环境中先停止 Runtime 和 Nginx，再清理二进制、静态资源和运行目录

## 6. 核心功能操作手册

### 6.1 快速上手

推荐按以下顺序开始使用：

1. 打开软件或浏览器入口
2. 检查规则配置与敏感词库
3. 上传单个文件或一批文件
4. 勾选需要启用的规则
5. 生成脱敏预览
6. 确认无误后生成正式结果
7. 对外发送脱敏文件，或将脱敏内容交给 AI 使用
8. 需要恢复时执行文件反脱敏

### 6.2 文件脱敏

文件脱敏用于生成可安全外发、共享或提交给 AI 的脱敏结果。

操作步骤如下：

1. 进入 `文件脱敏`
2. 选择一个或多个待处理文件
3. 勾选需要启用的内置规则
4. 根据需要启用敏感词库
5. 选择输出位置或确认服务器端处理流程
6. 点击 `生成脱敏预览`
7. 检查预览结果
8. 点击 `确认并生成正式批次` 或等价确认按钮

使用建议如下：

- 外发前优先预览，避免误删关键信息
- 批量文件较多时，先用一小批样本验证规则效果
- 如需提高识别覆盖率，可结合敏感词库和增强识别能力一起使用

分页处理补充说明：

- 对 `PDF`、`Word (.docx)`、`PowerPoint (.pptx)` 这三类文件，系统可显示总页数，并允许按页码范围处理
- 常见输入格式为 `1-10`、`5-15`；留空表示处理全部页面
- 页码范围适合抽样预览、处理特定章节，或分批处理超大文件
- 处理结果会在文件名中追加页码标记，例如 `文件名_脱敏_p1-10.txt`

预览阶段的快捷处理说明：

- 在手动查找替换区域中，识别到的敏感实体可直接点击标签主体加入替换列表
- 鼠标悬停时，标签左上角的快捷按钮可将该实体直接加入替换列表
- 标签右上角的删除按钮可移除误识别内容，避免重复操作
- 实体被加入替换列表或手动删除后，会从当前识别区域自动隐藏

### 6.3 文件反脱敏

文件反脱敏用于在编辑完成、审批结束或 AI 交互完成后恢复需要还原的信息。

操作步骤如下：

1. 进入 `文件反脱敏`
2. 选择对应的脱敏文件
3. 选择映射文件或引用系统中已保存的映射关系
4. 如映射文件已加密，输入正确口令
5. 选择输出位置
6. 点击 `开始反脱敏`

注意事项如下：

- 映射文件与脱敏结果必须配套使用
- 映射文件丢失、损坏或口令错误时，将无法恢复原文
- 反脱敏结果应视为敏感信息，恢复后需要继续按内部安全规则管理

### 6.4 规则与敏感词库

规则体系由内置规则和自定义敏感词库组成。

常见内置规则包括：

- 身份证号
- 手机号
- 电子邮箱
- 银行卡号
- IPv4 地址
- 护照号

敏感词库支持以下操作：

- 新增词条
- 编辑词条
- 启用或禁用词条
- 按分类管理
- CSV 导入
- CSV 导出

推荐做法如下：

- 将公司名、客户名、项目代号、地区名、组织名按分类维护
- 在正式批量处理前先抽样验证替换效果
- 对高频业务内容定期更新词库

列表管理补充说明：

- 敏感词列表支持搜索、分类筛选、分页查看和排序切换
- 排序可按创建时间或首字母顺序进行
- 当词条数量较多时，建议先按分类筛选，再做搜索和批量维护
- 对外高频出现但不适合使用正则规则的业务词汇，优先纳入敏感词库管理

### 6.5 沙箱与 PIN

沙箱用于保护本地或服务器侧的受控工作区。

常见操作包括：

- 设置共享或本地 PIN
- 解锁沙箱
- 锁定沙箱
- 清除 PIN

使用建议如下：

- 首次启用后立即设置可记忆、不可过于简单的 PIN
- 避免将 PIN 与映射文件放在同一公开位置
- 浏览器版中的沙箱状态通常由服务器统一维护，所有同一服务实例的会话可能共享该状态

### 6.6 FileBay 上传

FileBay 用于保存脱敏后的结果文件，不用于上传原始敏感文件。

操作步骤如下：

1. 管理员先完成 FileBay 服务地址、访问令牌和目标仓库配置
2. 用户进入 `FileBay 设置` 或相关上传入口
3. 验证连接状态
4. 从已完成的脱敏结果中选择要上传的文件
5. 确认目标仓库与远端路径
6. 提交上传

重要说明如下：

- 上传目标通常由管理员统一配置
- 映射文件和原始文件不应随脱敏结果一起上传
- 如果状态显示“未配置”或“配置无效”，请联系管理员处理

### 6.7 增强服务

增强服务主要包括 OCR 组件与可选的增强识别能力。

使用原则如下：

- 桌面版可由本机用户或管理员执行安装与检查
- 浏览器版通常只读显示服务器当前状态，安装与修复由管理员统一处理
- 未安装 OCR 时，扫描版 PDF 无法正确提取文字

### 6.8 操作日志

操作日志用于查看批次状态、处理结果和失败信息。

用户可执行的常见操作包括：

- 按状态筛选
- 按批次搜索
- 查看批次详情
- 查看失败原因
- 对失败项执行重试

管理员应重点关注以下情况：

- 大量批次连续失败
- OCR 超时频繁出现
- FileBay 上传持续失败
- 健康检查无法通过

## 7. 故障排查手册

### 7.1 常见现象与处理建议

| 现象 | 可能原因 | 建议处理 |
|---|---|---|
| 页面提示无法连接 Runtime | Runtime 未启动、Nginx 转发异常、网络暂时中断 | 先检查健康检查接口，再联系管理员 |
| 扫描版 PDF 无法识别文字 | OCR 未安装或不可用 | 由管理员安装或修复 OCR 组件 |
| 中文 PDF 提示字体编码异常或直接提取失败 | PDF 字体编码特殊，普通文本提取失败 | 优先直接重试预览；必要时启用 OCR，系统会在可用时自动回退 |
| 旧版 `.ppt` 无法处理 | LibreOffice 转换组件未就绪 | 由管理员检查 LibreOffice 安装 |
| 反脱敏失败 | 映射文件不匹配、口令错误、映射文件损坏 | 确认文件配对关系与口令 |
| FileBay 上传失败 | 未配置、令牌失效、仓库不可达 | 联系管理员检查 FileBay 配置 |
| 预览与正式结果不一致 | 规则切换、敏感词库变化、重复提交 | 重新确认当前规则与批次 |
| 文件内容已脱敏，但文件名中的敏感词没有变化 | 敏感词库未启用、词条未生效，或当前文件名不命中词库 | 检查批次是否启用了敏感词库，并确认对应词条为启用状态 |

### 7.2 管理员检查项

管理员可按以下顺序排查：

1. 检查 Runtime 健康接口： `GET /api/v1/health`
2. 检查前端入口与 `/api` 反向代理是否正常
3. 检查 OCR 解释器、脚本路径和模型目录
4. 检查 LibreOffice 是否可被调用
5. 检查 FileBay 四项配置是否完整且已重启生效
6. 检查运行目录权限、日志与持久化目录状态

更多部署级排查说明请参考：

- [`docs/enterprise/DEPLOYMENT.md`](./enterprise/DEPLOYMENT.md)
- [`SECURITY.md`](../SECURITY.md)

## 8. 合规、安全与隐私声明

本软件的设计原则如下：

- 优先在本机或企业内网处理敏感文件
- 支持通过映射文件与口令保护恢复能力
- 避免将原始敏感文件直接暴露给外部共享链路或外部 AI 服务
- 鼓励在正式对外交付前先完成脱敏，再做传播与协作

合规边界如下：

- 本仓库主许可证为 `Apache-2.0`

- 若对外分发内置 OCR 环境的镜像、安装包或客户交付物，需先完成额外许可证审查
