- 但文件名处理逻辑有问题

## 可能的原因

### 原因 1: 代码没有执行
如果终端中没有调试输出，说明 `mask_file` 函数根本没有被调用。

**可能的情况：**
- 使用了不同的代码路径
- 开发模式使用了缓存的旧版本

**解决方案：**
- 检查是否有其他的文件处理函数
- 确认开发模式使用的是新编译的代码

### 原因 2: 文件名没有匹配规则
如果代码执行了，但文件名没有变化，说明：
- 文件名中的内容没有匹配任何脱敏规则
- 原始文件名：`关于开展安全生产全员培训答题学习活动的通知`
- 脱敏后文件名：`关于开展安全生产全员培训答题学习活动的通知`（没有变化）
- 最终文件名：`关于开展安全生产全员培训答题学习活动的通知_脱敏.pdf`

**但是**，从截图看，连 "_脱敏" 后缀都没有，这不正常。

### 原因 3: 前端显示问题
如果实际文件名是正确的（有 "_脱敏" 后缀），但应用中显示不正确，说明是前端显示的问题。

**我们之前修改过前端显示逻辑：**
```tsx
{file.name.startsWith('masked_') ? file.name.substring(7) : file.name}
```

这会去掉 `masked_` 前缀，但不会影响 `_脱敏` 后缀。

### 原因 4: 使用了不同的保存路径
`mask_file` 函数会生成新的文件名，但可能在其他地方又被覆盖了。
