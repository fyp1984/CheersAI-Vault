# 文件名脱敏调试指南

## 更新内容
已添加详细的文件日志功能，用于调试文件名脱敏问题。

## 如何使用

### 1. 重新启动应用
编译完成后，重新启动 CheersAI 应用。

### 2. 处理一个测试文件
选择一个包含敏感词的文件进行脱敏处理，例如：
- `关于开展安全生产全员培训答题学习活动的通知.pdf`

### 3. 查看调试日志
处理完成后，在**输出目录**中会生成一个名为 `filename_masking_debug.log` 的文件。

**日志位置**：与脱敏后的文件在同一目录

### 4. 日志内容说明
日志文件包含以下信息：

```
=== 文件名脱敏调试信息 ===
时间: 2026-05-16 14:30:00
原始文件名: 关于开展安全生产全员培训答题学习活动的通知
脱敏后文件名: 关于开展安全生产全员培训答题学习活动的通知
应用的规则总数: 15
敏感词规则数量: 7
rule_ids 参数: ["id_card", "phone", "email", "use_sensitive_terms", ...]
use_sensitive_terms 是否启用: true

敏感词规则详情:
  - ID: sensitive_term_1, 名称: 培训 (敏感词), 模式: 培训, 替换: [敏感词], 启用: true
  - ID: sensitive_term_2, 名称: 考试 (敏感词), 模式: 考试, 替换: [敏感词], 启用: true
  ...

所有规则详情:
  - ID: id_card, 名称: 身份证号, 模式: ..., 替换: ***IDCARD***, 启用: true
  - ID: phone, 名称: 手机号, 模式: ..., 替换: ***PHONE***, 启用: true
  ...
================================
```

### 5. 分析日志

#### 检查点 1：`use_sensitive_terms 是否启用`
- **期望值**：`true`
- **如果是 `false`**：说明前端没有正确传递 `use_sensitive_terms` 参数

#### 检查点 2：`敏感词规则数量`
- **期望值**：> 0（应该等于数据库中启用的敏感词数量）
- **如果是 `0`**：说明敏感词没有从数据库加载

#### 检查点 3：`敏感词规则详情`
- 检查每个敏感词的：
  - **模式（pattern）**：应该是转义后的敏感词文本
  - **替换（replacement_template）**：应该是 `[类别名]`
  - **启用（enabled）**：应该是 `true`

#### 检查点 4：`原始文件名` vs `脱敏后文件名`
- **如果两者相同**：说明脱敏规则没有匹配到文件名中的敏感词
- **如果不同**：说明脱敏成功

### 6. 常见问题排查

#### 问题 1：敏感词规则数量为 0
**原因**：
- `use_sensitive_terms` 未启用
- 数据库中没有启用的敏感词

**解决方案**：
1. 检查前端 `RuleSelector` 组件
2. 检查数据库中的敏感词状态

#### 问题 2：敏感词规则存在，但文件名没有被脱敏
**原因**：
- 正则表达式模式不匹配
- 敏感词被转义后无法匹配中文

**解决方案**：
1. 检查日志中的 `模式` 字段
2. 验证正则表达式是否正确

#### 问题 3：文件名被部分脱敏
**原因**：
- 某些敏感词匹配成功，某些失败

**解决方案**：
1. 对比日志中的敏感词列表
2. 检查哪些词被匹配，哪些没有
